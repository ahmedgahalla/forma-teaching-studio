# 3.16 — Mechanics-aware scene explanations

**Branch:** `ahmed/phase-3-analysis-mechanics` · **Base:** PR #15 at `31a0eca` · **Date:** 2026-09-28 · **Status:** implemented; automated verification passed · **PR:** [#16 (draft)](https://github.com/ahmedgahalla/forma-teaching-studio/pull/16)

## Problem and resulting behavior

Analyze previously received wire details and appliance counts, but changing mechanical anchorage, support stiffness or elastic loading could produce the same explanation context. It could not reliably distinguish those experiments. This slice supplies the actual bounded configured inputs while retaining the distinction between editing locks, mechanical supports and calculated responses.

The existing Analyze control now sends support preset/coefficient facts, fixed tooth IDs, anonymous fixed-anchor coordinates, elastic endpoints and constant/spring laws, plus expander side groups, activation and stiffness. Wire facts and counts remain. A configured force is an input; it is not a measured or calculated force. No solver, scene, UI, lecture-authoring or response-action behavior changes.

## Contract and privacy

- Support values come directly from the frontend's existing engineering presets: standard 100 N/mm and 1,000 Nmm/rad; soft 50/500; firm 200/2,000. The server independently requires the matching pair. These are virtual teaching assumptions, not measured tissue coefficients.
- `fixedTeeth` expresses mechanical anchorage. Each tooth's existing `locked` value continues to express only its geometric editing lock.
- Anchor IDs become request-local `tad-1` through `tad-8`; endpoint references use those same aliases. Elastic/expander IDs and arbitrary nested metadata are omitted. All emitted arrays and nested objects are copied explicitly.
- Absent mechanics has null support and empty appliance lists. An absent optional palate spring is explicit null. The server rejects contradictory counts, unavailable/duplicate references, unsupported bounds, extra fields and a result without a configured synthetic experiment.
- A result remains visible only when it is current, synthetic and explicitly revealed. Stale, hidden, applied and comparison results are not substituted. Lecture notes and unrevealed answers retain the prior protections.
- Provider instructions distinguish scene-space anchor coordinates from tooth-local attachment coordinates and explicitly identify the missing reference origins/orientation/slot data. The AI must not infer force directions, moment arms, net forces or outcomes from incomplete geometry. The reply remains strictly read-only.

The five new appliance fields are required. Update the frontend and restart the backend from the same revision; mixed versions receive the normal sanitized validation error. Defaults are not invented to make incomplete legacy facts look complete.

## Files and decisions

- `src/lib/scene-analysis.ts` and its tests: explicit fact projection, anonymization, snapshot independence, support/lock distinctions and result gating.
- `backend/scene_analysis_appliances.py`: bounded appliance models and reference/count validation extracted from the endpoint module to keep files below 300 lines.
- `backend/scene_analysis.py`: current scene consistency, configured-versus-calculated instructions and `from` alias serialization.
- Backend scene-analysis tests: valid facts reach the mocked provider exactly; invalid contracts fail before provider invocation and retain error sanitization.

The source review also found that expander settings had the same counts-only omission, so this slice includes their existing inputs. No new mechanics are introduced. Provider cancellation stays separate in the next slice; broader CSS, case-view props and Try Mode refactors do not overlap this correction.
