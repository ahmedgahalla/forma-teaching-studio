## Gingiva

Before, the gum meshes only translated as complete arches for jaw separation. Individual tooth movement left them unchanged. The new viewer-owned deformation uses nearby crown/root surfaces to blend local tooth following, with reduced influence toward the palate and gum base. It reads the actual displayed tooth groups, including magnified mechanics response, instead of independently resampling a second animation.

The source position/material data remain immutable. Poses always apply to the original gum vertices; replay does not accumulate deformation. Rest restores the original positions and smooth normals exactly. Lower-arch opening is accounted for once, and hidden or unchanged gums avoid redundant updates. Influence data and scratch buffers are cached; display geometry is disposed by the existing viewer ownership path.

The normal demo loads generated bindings for both complete arches and the space-closure lecture's upper premolar-extraction subset. Source/payload checksums and descriptor validation reject mixed snapshots; a source/generator fingerprint test detects stale generated files. The cache also recognizes rigid registration changes and matching saved geometry. Unmatched custom source geometry computes its own bindings. Rebuild with `node --experimental-strip-types scripts/generate-atlas-gum-bindings.mjs` after formatting any binding inputs or changing the snapshot. Runtime checksums detect ordinary corruption/staleness; they are not authentication signatures.

Class I/II/III arrangements now put their rigid arch offsets in matching tooth and gum rest origins, preserving every displayed world pose while avoiding a doubled gum offset. Their saved mechanics references round-trip. Older arrangement files use the same case version without a marker for the old convention: they remain loadable but may over-follow. Reopen the corresponding built-in arrangement for corrected following; no speculative migration changes an old saved setup.

This is illustrative soft-tissue following. It does not calculate remodeling, recession, tissue stress or the biology of a tooth moving through bone. Unsupported atlas bone/ligament sleeves remain unavailable.

## Bracket controls and mechanics

Inside Mechanics → Brackets & wire, select one tooth with an installed bracket and open **Bracket position · tooth …**. Move its bonding location mesially/distally and toward the biting edge/gum, each within ±2 mm of the authored site. Adjust **Angle on crown** within ±10°. Positions are projected onto the actual buccal crown surface; a missed crown is rejected before dispatch. These ranges are teaching-model bounds, not bonding recommendations.

The angle is an in-plane rotation about the outward buccal axis. It is separate from wire torsion, bracket prescription torque and curvature-induced torque. The displayed bracket and the solver use the same slot centre. The renderer's captured updater preserves registration and creates no per-frame vectors.

The original reference slot curve remains the passive wire. Changing a bond site changes its bending mismatch and force lever arm; changing angle changes the small-angle seated end slope. This also works for round-wire bending. Brackets without an engaged wire produce no wire response. Ideal axial sliding remains: a purely along-wire shift need not create a load. Existing explicit elastic endpoints remain independently positioned; this change does not rebind them automatically.

**Research:** Miethke's primary study documents how bonding height and crown morphology affect torque expression ([PubMed](https://pubmed.ncbi.nlm.nih.gov/9282545/)). It supports teaching the importance of placement; its measurements are not converted into a universal angle-per-millimetre rule here. This implementation demonstrates the bounded elastic model's geometry and in-plane bending, not that study's clinical torque effects.

Apply and Reset use validated mechanics actions and the existing request-level Undo/Redo. The selected bracket's committed values survive save/restore and experiment stages; reinstall preserves edits. Partial typing survives unrelated updates, and selection/Undo refresh the editor. Angle-only Apply preserves exact untouched coordinates. After a calculated response, edits recalculate only when activation remains; a neutral reset returns to the unchanged reference without a rejected passive solve.

Frontend compound-request context and optional backend validation carry the angle map and use matching activation rules. Analyze receives bounded slot/reference-slot coordinates and the in-plane angle, without new inferred force or outcome claims. Older payloads without those facts retain their previous shape.
