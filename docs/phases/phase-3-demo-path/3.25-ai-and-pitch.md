## Problem and result

The owner requested OpenAI connection repairs and a feature video for Professor Nael. The active demo checkout has no private backend configuration, normal startup launches only the static app, and default backend CORS origins omit the active port 3012. Configuring a key elsewhere does not connect this exported app.

`npm run start:ai` now launches the existing Python Responses backend and exported frontend together, waits for Python's successful bind, and advertises the service through a safe same-origin runtime configuration. It sets the exact local origin, keeps provider secrets in the backend process and stops both children together. Existing saved settings and deliberate AI opt-outs remain authoritative. Ordinary startup is unchanged. See [backend setup](../../../backend/README.md) for private configuration and reconnecting an existing profile.

The fixed local gateway forwards only health and the two existing teaching endpoints. It requires loopback binding, checks Host/Origin, limits JSON requests/responses to 64 KiB, bounds concurrency and total duration, and propagates cancellation. It does not expose an arbitrary proxy or forward browser credentials. Existing schema/action validation and the geometric/mechanical runtime remain unchanged.

The saved provider configuration belongs to OpenRouter and selects an OpenAI model. Provider choice and live verification were pending at this slice's original handoff. The owner subsequently chose the existing OpenRouter setup; [3.28](3.28-ui-ai-reliability.md) records the authorized private configuration, passing live command/explanation checks and Windows startup fix. The default model and existing Responses integration were checked against [OpenAI's model documentation](https://developers.openai.com/api/docs/models/gpt-6-luna) and [structured outputs guidance](https://developers.openai.com/api/docs/guides/structured-outputs); the default model is unchanged.
