## Goal and final scope

The owner's latest instruction replaces teacher-created lecture authoring with a finished sample: open Lecture and teach immediately, or use Explore freely. This **consolidated first vertical slice** retains the shared workspace, deterministic runner, exploration return and bounded inputs from the [teacher-workspace proposal](https://github.com/ahmedgahalla/forma-teaching-studio/pull/12). Its proposed 3.10–3.14 milestones are not a duplicate pending roadmap. The editor and persistence portions have been deliberately removed rather than left as promised next steps.

Before this slice, the app had prepared cases and developer-authored workflows. It now also has a complete four-step translation-versus-tipping lecture with presenter notes, prediction questions, answer reveals and a route into a spontaneous model experiment.

## Teacher experience

- **Lecture** opens the finished sample directly in Teach. There is no lecture creation screen, local lecture library, Prepare mode, title/notes editor, scene capture, attachment editor, import, export or lecture save action.
- **Teach** starts with notes collapsed and answers hidden. **Rehearse** uses the same model steps with notes exposed. Every newly loaded step hides its answer. **Opened notes appear on the same projected window as the model; they are not private presenter notes.**
- Previous/Next and supported typed step jumps restore absolute authored states. The two demonstrations restart at frame zero. Repeating navigation cannot accumulate tooth movement.
- One model playback strip operates the current demonstration: Play/Pause, scrub, restart and speed. Step navigation changes the lecture step. The introduction and recap are static views without inferred animation.
- **Explore this question** pauses the lecture and opens a temporary experiment. **Return to lecture** restores the paused frame, camera, layers, answer and notes visibility. The standalone Explore workspace from before the lecture is preserved separately and restored on exit.
- Scene-changing navigation refuses unresolved edit/drag previews. Apply or discard first. Shared runtime cancellation prevents late interpretation results from applying to another step; whole-request undo/redo includes lecture state.
- Model experiments do not edit the built-in content. The runner has no lecture-storage access; earlier browser lecture saves are neither read, migrated nor deleted. Return snapshots exist only during the current session and do not survive reload.

Buttons, typing and recognized voice commands share validated actions. Examples are `next step`, `previous step`, `go to step 2`, `show notes`, `hide notes`, `reveal answer`, `hide answer`, `rehearse lecture`, `teach lecture`, `explore this question`, `return to lecture`, `restart lecture` and `exit lecture`. Use one lecture control per request, with scene instructions separately. Lecture controls do not need the AI backend. Existing hold-to-talk and explicitly enabled hands-free input remain available; browser speech recognition is not guaranteed offline. There are no Prepare or lecture-library commands.

## Finished sample: translation versus tipping

`createLectureSample(): LectureDocument` produces fixed validated data, with stable document/step identifiers and update date. It accepts no workspace scene, reads no storage and generates no random content. Every opening uses the canonical `movement-types` case, upper incisor 11 selected, roots visible and appliances hidden.

| Step                                  | Display and teaching purpose                                                                                                                      | Suggested allocation |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| 1. Predict: position or orientation?  | Hold the prepared baseline. Ask students to choose crown and root points and predict how their paths distinguish translation from tipping.        | 35 seconds           |
| 2. Translation: the same displacement | Play the existing `translation` variant from its authored start. Pause, follow both points, then reveal its existing question/answer explanation. | 60 seconds           |
| 3. Tipping: a change in orientation   | Reset to the same baseline and play the existing `tip` variant. Compare orientation and point paths, then reveal its existing explanation.        | 65 seconds           |
| 4. Recap: describe what changed       | Hold the authored tipping endpoint. Ask for a one-sentence comparison; optionally explore a question and return.                                  | 45 seconds           |

The **205-second total (3 minutes 25 seconds) is an estimate, not a measured rehearsal**. An extended question detour can take longer. Full presenter notes accompany all four steps. The demonstrations and scientific scope reuse existing audited case content: prescribed geometric paths about displayed crown-centred pivots, without forces, biological response or treatment timing. No new clinical claims, case assets or trajectories are introduced.

## Excluded

Lecture authoring and saving, PDF/PowerPoint or JSON lecture import/export, a separate audience window, cloud accounts/sync, arbitrary animation, automatic notes-to-motion, private presenter notes and new biology content are outside this revision. Existing Explore tools remain available, but cannot overwrite the fixed sample. Any future authoring or audience-screen work needs a separate product decision.
