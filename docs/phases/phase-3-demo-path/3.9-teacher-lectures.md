**Dependency:** the inherited Phase 3.2 opening work in [PR #13](https://github.com/ahmedgahalla/forma-teaching-studio/pull/13), followed by the Phase 4 voice, tooth-study and presentation work. This branch is not a claim that those dependencies or this implementation have merged.

## Goal and scope decision

The owner requested one complete teacher journey: explore the model freely, or prepare a lecture inside Forma and teach it alongside saved notes and model steps. The approved bounded implementation combines that Explore/Lecture structure with the existing Phase 4 interaction layer. It adds no new anatomy catalogue, solver or AI-generated motion.

This is the **consolidated first vertical slice** of the teacher-workspace proposal in [PR #12](https://github.com/ahmedgahalla/forma-teaching-studio/pull/12). The proposal's 3.9 navigation and proposed 3.10–3.14 document/editor/runner/return/input deliverables are implemented together here to make the journey usable end to end. Those proposed numbers are not a second pending implementation roadmap. Broader playback consolidation, visual polish, offline assets, biology and real-device rehearsal retain their separate scope.

Before this change, the app could run developer-authored lessons and workflows, but a teacher could not write and save a custom sequence of notes and model setups. After this change, the teacher can create that sequence, reopen it, teach it and explore a question without replacing its saved content.

## What the teacher can do

### Explore and prepare

- **Explore** retains the model workspace, built-in Library, supported commands and advanced tools. **Lecture** opens the teacher's local lecture library. Prepare, Rehearse and Teach are views within Lecture.
- Create a lecture from the current supported synthetic view, or create the three-step translation/tipping sample. Open an existing lecture or import a Forma lecture backup.
- Write the lecture title and ordered steps. Each step has a title, plain-text notes, an optional student question and an answer that can be revealed separately. Add, duplicate, move and delete steps; the editor keeps at least one step.
- Use **Capture shown model setup** to explicitly replace a step's saved scene. Editing the live model does not automatically change its saved scene. Capturing an attached demonstration replaces it with the static view currently displayed.
- Alternatively, choose a prepared case and variant and press **Attach demonstration**. This explicitly adopts that example's compatible starting model, arrangement and display setup. Play uses its existing authored trajectory; it does not animate between arbitrary saved views.
- Delete step and delete lecture actions require confirmation. There is no trash or authored-document deletion undo. Export a backup before deleting content that may need recovery.

### Teach and rehearse

- Rehearse and Teach use the same saved steps and scene runner. Teach starts with notes collapsed; Rehearse exposes notes. Answers start hidden whenever a step is loaded.
- Previous, Next and direct step selection restore absolute saved states. Attached demonstrations restart at their authored zero frame; repeated navigation does not accumulate tooth movement.
- Lecture step navigation is separate from the existing model playback strip. Next changes the step; Play/Pause/scrub operate on its attached demonstration. Static steps have no inferred animation.
- Show or hide notes and reveal the answer deliberately. **Opened notes are visible on the same projected window as the model; they are not private presenter notes.** Reading or scrolling notes does not execute model actions.
- **Explore this question** pauses and preserves the current lecture moment while opening a temporary experiment. **Return to lecture** restores its paused frame, camera, layers and question/answer state. Returning does not rewrite the saved lecture. The standalone Explore workspace from before opening the lecture remains separately available on exit.
- Pending edit/drag previews must be applied or discarded before scene capture or navigation. Lecture navigation uses the shared runtime, including cancellation and whole-request history; late interpretation results cannot apply to the newly selected step.

The lecture and temporary return snapshots are session state. Reloading can reopen the saved lecture document, but does not recover the interrupted live frame, an unsaved model experiment or the earlier standalone Explore workspace.

### Local notes, backups and input

Valid lecture changes are autosaved in this browser under a versioned library key, with a visible saved/not-saved status. Browser storage is local to this device and origin. Storage quota or permission errors keep current work in memory and report that a backup is needed. Corrupt saved data is not silently replaced with an empty library.

Export writes a validated `.forma-lecture.json` backup. Import creates a new lecture identity so an older backup cannot silently overwrite newer local work. Documents support up to 100 steps; individual backups are limited to 10 MiB. Browser quota can be lower than the format limits. Unknown versions, invalid model references, absent tooth IDs, non-finite poses and mismatched case/variant references are rejected before scene use.

Buttons, typing and recognized local voice commands use the same bounded presentation actions. While a custom lecture is open, examples include:

```text
teach lecture
rehearse lecture
prepare lecture
next step
previous step
go to step 2
show notes
hide notes
reveal answer
hide answer
explore a question
return to lecture
restart lecture
exit lecture
```

Use one lecture control per request, then give scene instructions separately. These operations do not require the AI backend. Existing hold-to-talk and explicitly enabled hands-free recognition remain the input mechanisms; browser speech recognition is not guaranteed offline. The lecture builder does not add voice dictation for notes.

## Scene and persistence decisions

- The saved scene stores the **visible** tooth poses, including the displayed magnification, rather than an unseen target or unscaled mechanics response. Static playback is normalized to the captured endpoint.
- Geometry is not serialized. A supported source descriptor rebuilds the canonical reference mouth, prepared case or dental arrangement; scene data supplies poses, camera, selection/isolation, layers, appliance settings, attachment metadata and optional tooth-study presentation.
- Source identity remains attached to restored static scenes. Recapturing a case-derived view therefore preserves its registered origins and omitted teeth even without an active prepared demonstration.
- Imported/custom models and arrangements transferred from the workflow classroom cannot be captured into lecture steps. Existing import and workflow tools remain available in Explore. Only prepared case variants can be attached as demonstrations in this slice.
- Mechanics is captured as static shown poses plus validated appliance inputs. Its reference teeth and reference transforms are rebased together; computed result, applied result and comparison result are not persisted. Opening a step does not infer or replay a mechanical response.
- Document copies and duplicated steps own independent plain data. In-session scene snapshots retain the existing renderer/model references for exact restoration; they are not used as the disk format.
- Authored lecture content, live teaching state and temporary exploration remain separate. Attaching a demonstration or capturing a new setup is explicit. Navigation and mode changes stop ongoing work through the existing runtime.

## Proposed 3–4 minute demonstration — not yet timed

Prepare the sample beforehand from the synthetic mouth. Give its first step a short introduction; retain the existing authored translation and tipping questions/answers. Export a backup. The timings below are rehearsal allocations, not measured performance.

| Target time | Teacher action                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:25   | Open the saved sample, choose Teach and introduce the model with notes collapsed.                                                   |
| 0:25–1:15   | Next to translation; ask the saved question, play and pause the illustration, then reveal its explanation.                          |
| 1:15–2:05   | Next to tipping; ask for a prediction, play and compare the visible root/crown paths using the existing authored example.           |
| 2:05–2:55   | Pause at an intermediate frame, choose Explore this question, change the camera or make a bounded preview and resolve that preview. |
| 2:55–3:25   | Return to the exact paused lecture moment, then go Back/Next to show repeatable prepared starts.                                    |
| 3:25–3:45   | Exit to the independent Explore workspace and explain that the saved lecture remains reusable.                                      |

Run and time this route in a real browser before calling it a successful demo. Then test the affected prepared-case, braces-workflow and typed-command paths at DPR 1 and 2. Microphone recognition, cold local operation without the AI backend, and projector readability need actual device checks; test doubles and a build do not establish them.
