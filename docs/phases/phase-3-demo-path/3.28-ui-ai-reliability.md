## Goal and before/after

The owner requested a clearer overall UI and a fix for the OpenAI issue. The existing Claude Atlas appearance and central model remain the design reference. This slice concentrates on lecture navigation, teaching controls and AI connection recovery rather than adding modes or changing anatomy.

- Previously, the fourteen-step case exposed a count and previous/next navigation. Named step selection now goes through the existing validated `presentation/go` action, with one progress indicator and a stronger Next action. A question detour disables lecture navigation until Return.
- Questions and Reveal are the primary teaching controls. Notes remain separately accessible. Focus, comparison and biology setup live in Teaching aids; active comparison/biology keep their return controls available when that disclosure is closed.
- Atlas header controls have larger interaction targets and clearer focus states; the Explore label matches the workspace language. Lecture controls wrap for smaller widths. Appearance and projector readability still require browser acceptance.
- Settings now offers an explicit Connect this app/Reconnect path using strict same-origin discovery, with manual backend URL entry under Advanced. Saved opt-out is respected until the teacher chooses to reconnect. No frontend key field is added.
- Both command interpretation and scene explanation share bounded, cancellable network handling. Wrong endpoints, HTML responses, missing keys, provider permissions/model failures, timeouts and billing limits have actionable messages. Only fixed safe backend messages are exposed. A static-only app reports the missing gateway with startup instructions instead of repeating reconnect advice.

## AI diagnosis and configuration boundary

Read-only configuration inspection found that this demo worktree has no `backend/.env` and no inherited key. The original project has a private OpenRouter configuration. These facts explain a missing local setup; they do not establish the provider account's live health. The owner was asked whether to reconnect the existing OpenRouter provider or configure direct OpenAI. No private settings have been copied and no provider request has been made while that choice is pending.

`/health` proves that the backend is reachable and a key is configured, not that the key, model access or credits work. Settings and the footer no longer imply that provider access has been verified. Local typed controls remain available when AI is off or a provider request fails.

Provider error classification follows [OpenAI's error guidance](https://developers.openai.com/api/docs/guides/error-codes), checked 2026-09-29. Quota, organization/project spend and usage limits need billing/settings action; temporary rate limits may be retried. Upstream messages and keys are never reflected into the browser.
