# 3.20 — Crown and root movement trails

**Branch:** `ahmed/phase-3-crown-root-trails` · **Base:** draft PR #19 at `59750c5` · **Date:** 2026-09-28 · **Status:** implemented; automated checks passed; browser acceptance pending · **PR:** pending

## Goal and scope

The owner approved improvement #2: labelled crown/root points and movement trails. Further lecture features and content are deferred until the professor sees the demo, approves the direction and supplies lectures/cases. The existing fixed sample remains unchanged.

Before, Displacement traces drew a straight centre-to-centre segment for each tooth, even when the tooth followed a curved or multi-stage path. After, the primary selected tooth has a labelled crown point with a solid path and, when real root geometry is present and roots are visible, a labelled root point with a dashed path. Shapes distinguish the points as well as colour. The paths show only movement already reached, including when seeking or playing in reverse.

## Use and design

1. Select the tooth whose movement you want to explain.
2. Enable **Schematic roots** and **Displacement traces** in the existing display controls. The existing local command **show displacement traces** also works; **hide displacement traces** removes them.
3. Play or scrub an authored demonstration, Try preview, staged plan or calculated mechanics response. The points follow the displayed tooth. Selecting another tooth replaces the two paths.

- `displayed-motion.ts` and `case/useDisplayedMotion.ts` share the existing source priority and exact sampler between Studio and the trails: prepared keyframes, rigid/linear Try motion, checkpoints, then the existing mechanics override. Actual mechanics measurements remain unscaled while the paths follow the visible magnification.
- `movement-trails.ts` chooses an actual occlusal-extreme crown vertex and an actual root terminal branch point (or rootward extreme geometry vertex where branch metadata is absent). A multi-root tooth uses one real branch endpoint. These are geometry reference points, not estimates of a centre of resistance or clinical apex. Uncalibrated imports do not receive inferred anatomy.
- The helper samples 64 intervals plus exact authored/checkpoint breakpoints outside the render loop. It never accumulates frame history. `useMovementTrail` rebuilds on source/selection changes, including undo, but retains its path through scrubbing, pausing and camera changes.
- The renderer keeps fixed buffers, draws earlier samples plus the exact live endpoint and applies lower-jaw display separation once. Hidden mechanics, direct dragging, tooth study, hidden teeth and disabled traces suppress the paths. Hidden roots suppress the root cue independently. Stationary points retain markers without zero-length lines.
- In-canvas labels share existing snapshots and audience capture; no new public overlay protocol is needed. Text, marker size and line width use CSS dimensions; colours follow existing light/dark palettes. Actual DPR, clipping and projected readability remain unverified.
- The toggle now uses the validated, undoable runtime action. Trace display is allowed in prepared and ordinary case contexts as well as Try Mode; curve/reverse controls keep their prior restrictions. The action remains local-only, with no AI/backend authority expansion.
