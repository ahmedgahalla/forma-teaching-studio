# 3.31 - Keep the learner in control of the view

**Branch:** `ahmed/phase-3-user-controlled-view`
**PR:** Pending draft creation.
**Base:** PR #30 (`ahmed/phase-3-learning-appliances`) at `3106cea`.

## Goal and scope

The owner requested that the model and important information stay central, and that a selected camera view continue through lecture steps until the user changes it. They also requested a concise, one-minute, continuous screen recording for Professor Nael, without edits or effects.

The existing full-width learner layout and short captions remain. This slice separates authored scene changes from the learner's camera: Next, Previous, named-step jumps and restart change teeth/appliances while retaining the current view and captured orbit, pan and zoom. Opening a different lecture uses its prepared first view; reopening the current lecture remains a no-op. In occlusal view, the visible arch is also retained so the other arch cannot suddenly cover it. Other anatomy and appliance settings continue to follow the authored step.

The view menu exposes the active camera name, such as 3D view or Occlusal view. Explicit view buttons, Fit, orbit gestures and Focus/Show surrounding teeth remain available. Focus changes initiated by the user can reframe; a new step's selected teeth must not trigger an automatic preset refit. Actual window resize may adapt framing while preserving the viewing direction. If new hardware falls outside a deliberately close view, Fit explicitly includes the visible teeth and appliances.

Comparison arrangements hold the camera and its view label consistently. Exact comparison/Explore return points, request-level Undo/Redo and cancellation remain intact. There is no preference database, camera lock mode, global Explore behavior change, model/clinical content change or new appliance calculation.

## Implementation and verification

`scene-bridge.ts` optionally carries the captured camera and named view into an otherwise absolute authored snapshot. The session enables that only for the same lecture, and both comparison paths reuse it. `viewer-camera-policy.ts` suppresses automatic learner refits while consuming visibility changes, allows explicit focus changes and retains the camera across model reconstruction. CaseViewport enables this only for the learner workspace. The extracted frame cache keeps the existing effective visibility values and a separate jaw cache for the curve overlay; no per-frame state object is allocated. Viewer shrinks from 1,129 to 1,113 lines.

Focused runtime coverage exercises click/typed/voice navigation, camera-null fallback, stale view labels, occlusal arches, different-lecture entry, comparisons, exact returns, Undo/Redo and cancellation. Camera-policy tests distinguish authored changes from explicit focus, verify no delayed refit on exit and retain existing Explore behavior. Existing motion and resize tests cover pose holding and resize direction. The compound view-plus-navigation grammar remains rejected; sequential commands work.

The final automated gate passes: **3,112 frontend tests in 177 files**, **659 backend tests**, TypeScript, ESLint with zero warnings, Prettier, file limits (568 files), production static build and offline demo-asset checks. Twenty-two frontend cases were added; none were removed. All contributors froze before the final run. The local frontend build has been refreshed, with existing listeners confirmed on ports 3012 and 8002. Early focused verification caught an incorrect test assumption about compound commands and the extraction's shared curve-jaw cache; both were corrected before the final gate. AGENTS.md and auditor-owned STATUS.md remain untouched; broader CSS, prop-narrowing and try-mode inbox items stay open.
