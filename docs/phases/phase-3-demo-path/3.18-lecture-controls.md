# 3.18 — Consistent lecture entry and view controls

**Branch:** `ahmed/phase-3-lecture-controls` · **Base:** draft PR #17 at `22fd450` · **Date:** 2026-09-28 · **Status:** implemented; automated verification passed · **PR:** pending

## Evidence and scope

A requirements check of the implemented teacher workflow found two concrete gaps. Clicking Lecture opened the finished sample, but the same entry was unavailable through local text/voice parsing because lecture commands required an already active presentation. The simplified lecture heading also removed the only clickable camera/Fit menu, while the lecture layout hid the remaining layer controls. Teachers could type camera and root commands but could not make the equivalent clicks.

This slice restores those requested controls without adding another mode, lesson editor or large toolbar. The separate audience-annotation finding is tracked for the next slice in [the review record](../../reviews/from-builder/2026-09-28-lecture-control-gaps.md).

## Resulting behavior

- `lecture`, `open lecture`, `open sample lecture` and `start sample lecture` open the same fixed sample as the top-level Lecture button. Reopening the active sample retains its current step, reveal state, discussion return point, playback and Undo/Redo history.
- During a sample lecture, `explore` and `return to explore` exit to the original standalone Explore workspace, matching the top-level Explore button. `Explore this question` remains the temporary detour with a separate Return to lecture action.
- Legacy `start lecture` / `enter lecture mode` retain their existing Present-layout meaning for compatibility; `open lecture` explicitly names the finished sample.
- A compact lecture View disclosure contains camera presets and a roots toggle, with Fit next to it. The new Fit command uses a bounded local presentation action and the existing viewer's preset-fit behavior, preserving the lecture's saved return points.
- Clicks, typed commands and recognized local speech use the same validated operations. Entry/exit and Fit remain local with AI preference enabled. Unresolved previews, dragging and loading continue to prevent scene-changing navigation. No command expands the backend's authority.

## Implementation and review corrections

`classroom/presentation.ts` shares exact sample-entry parsing with the runtime's local-control helper. The fixed sample ID lives in a small data constant, avoiding a parser dependency on the complete sample content. Session preflight and execution recognize the already active document. The runtime additionally recognizes an exact, validated redundant open before interrupting playback or modifying history; compound and malformed requests continue through normal validation. The existing playback wait moves unchanged to the existing async helper to keep the allowlisted runtime from growing.

`LectureViewControls` accepts only view, roots and the validated execution callback. `CaseMain` places it beside the complete lecture title and keeps the existing Explore heading during a question detour. The disclosure uses the existing keyboard/focus behavior and overlay exclusion class. Buttons have 44px minimum height. Its popup is anchored and width-bounded to the full heading, avoiding the inherited viewport-width/mobile-offset assumption. This CSS contract is checked in DOM tests; no pixel-layout claim follows from that test.

Files touched: lecture parser/sample constant; local runtime/async helper; lecture session and fixtures; the new View component, heading and scoped styles; co-located parser/runtime/component tests and the existing provider routing test. Phase, product-direction, architecture, lessons, review and handoff records are updated. No teaching-case content, solver, assets, backend, lockfiles, AGENTS or STATUS changes. No tests removed.

The narrower case-view props, Try Mode split and general CSS cleanup remain separate auditor follow-ups. This change uses narrow props for its new control without refactoring unrelated callers. Public audience annotations remain a separate correction; lecture authoring stays excluded.
