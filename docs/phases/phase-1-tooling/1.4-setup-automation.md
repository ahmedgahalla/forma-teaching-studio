# 1.4 — Setup automation

**What was done**

- **One-command setup:** `npm run setup` (`scripts/setup.mjs`) checks the Node version against `.nvmrc` (and the ≥22.6 strip-types floor) and finds a Python ≥3.13, with clear errors for what it can't fix itself; then runs `npm ci`, creates `backend/.venv` if missing and installs `requirements.txt`, and sets `git config blame.ignoreRevsFile .git-blame-ignore-revs` + `core.hooksPath .githooks`. Safe to rerun.
- **Auto-sync after pulls:** `.githooks/post-merge` and `.githooks/post-checkout` (shared `sync-deps.sh`) rerun `npm ci` only when `package-lock.json` changed and the backend pip install only when `backend/requirements.txt` changed. Hooks never fail the git operation. They're enabled automatically by the npm `prepare` script (`git config core.hooksPath .githooks`), so the first `npm ci` switches them on. No husky or other dependency.
- **Session start protocol** (AGENTS.md) gained a step: verify dependencies are in sync, run `npm run setup` if not.
- **README** gained a "Getting started" section: install Git / Node 22 / Python 3.13, clone, `npm run setup`, everything else is automatic.

**Files touched:** `scripts/setup.mjs`, `.githooks/*`, `package.json` (`setup`, `prepare`), `AGENTS.md`, `README.md`, `docs/lessons-learned.md` (lesson 7).

**Decisions:** plain git hooks via `core.hooksPath` instead of husky — no dependency, no install step, and the `prepare` script makes enablement automatic.

**Skipped / notes:** the hooks are POSIX sh (Git for Windows runs them with its bundled sh); they pick the right venv python for Windows (`Scripts/`) or Unix (`bin/`).
