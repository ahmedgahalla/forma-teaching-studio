# 1.7 — Node version policy (post-merge follow-up)

**Branch:** `naser/node-version-policy` · **Owner:** auditor (Claude Code) · **Requested by:** Naser, 2026-09-26

Originally authored as 1.5; renumbered to 1.7 before merge because 1.5 is reserved for PR #3 (`ahmed/local-project-setup`, merges separately) and 1.6 was taken by the PR lifecycle delegation doc merged in the meantime.

## Why

Naser's machine runs Node 24.11.1; the other developer's version is unknown. The
tooling previously read as if Node 22 were the only supported version: `npm run setup`
printed a "newer than the pinned 22" warning on any newer major, CI ran only Node 22
(via `.nvmrc`), and AGENTS.md/README said "Node 22" flat. `engines` already allowed
newer versions (`>=22.6`), so the range existed but was implicit and untested.

## What was done

- **Policy made explicit: Node 22 or newer is supported.** The exact floor stays
  **22.6** because the `--experimental-strip-types` scripts
  (`scripts/generate-samples.mjs`, `scripts/audit-teaching-cases.mjs`) need it —
  `engines: ">=22.6"` in package.json is unchanged and already expressed this.
- **`scripts/setup.mjs`:** the version check no longer compares against `.nvmrc`'s
  major; it enforces the ≥22.6 floor directly and reports any newer version as a
  plain pass (no warning). The now-unused `readFileSync` import was removed.
- **`.github/workflows/ci.yml`:** the frontend job runs a matrix on Node 22 and
  Node 24, so both ends of the supported range are tested on every PR. The backend
  job is unchanged (Python 3.13).
- **AGENTS.md:** the verification-gate CI sentence now says Node 22 **and** 24, and a
  new "Node version policy" paragraph records the range, the 22.6 floor and its
  reason, and `.nvmrc`'s role as the nvm baseline. (AGENTS.md changes require a PR
  agreed by both developers — this PR is that agreement vehicle.)
- **README:** "Getting started" now says Node 22 or newer (floor 22.6) and states the
  policy in one line.
- **`.nvmrc` stays at 22** as the recommended nvm baseline; it no longer implies an
  upper bound anywhere.

## What was skipped and why

- No new ADR: this refines the environment pinning recorded in ADR 002 rather than
  reversing it — the pin becomes an explicit supported range, documented in AGENTS.md.
- Historical phase docs (1.1, 1.4) were left describing the behavior they shipped;
  this doc records the change.

## Verification

Full gate run on this branch (results in the PR); no UI change, so no browser check —
no screen is affected. The CI matrix itself is proven by the PR's own checks
(frontend on 22 and 24 both green).
