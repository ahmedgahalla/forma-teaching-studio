## Start work

Check the working tree first. If it contains unfinished changes, commit them on their existing work branch before switching. Do not discard someone else's work to make a pull succeed.

```sh
git status
git switch main
git pull --ff-only origin main
git switch -c ahmed/short-description
```

Naser uses `naser/short-description`. Choose a new, descriptive branch name for each task. Follow the session protocol in `AGENTS.md`, including reading the review inbox and checking dependencies.

## Share completed work

Run the repository verification gate and update the relevant phase and handoff docs. Stage only the intended files; inspect the staged diff before committing.

```sh
git diff --cached
git commit -m "Describe the completed change"
git fetch origin
git merge origin/main
git push -u origin HEAD
```

Resolve any merge conflicts and repeat affected checks before pushing. Open a pull request against `main`; do not push directly to `main`. The auditor reviews and merges through the existing CI and merge-commit rules in `AGENTS.md`.

Once a PR is merged, both developers receive it by switching to a clean `main` and running `git pull --ff-only origin main`. An open PR is available after `git fetch origin`, but is not part of `main` until merged. Inspect it on a separate branch or worktree when needed.

## What is automatic

`npm run setup` installs dependencies and configures the existing `post-merge` and `post-checkout` hooks. Those hooks re-install dependencies when their tracked lockfiles change. They do not automatically pull, publish, merge, or run the verification gate. A hook installation failure requires rerunning setup before continuing.

The dedicated checkout uses local Git settings `pull.ff=only` and `fetch.prune=true`. A divergent pull therefore stops for inspection instead of making an unexpected merge. Other developers can apply these local settings too:

```sh
git config --local pull.ff only
git config --local fetch.prune true
```

GitHub authentication is separate from dependency setup. Use `gh auth login --hostname github.com --git-protocol https --web` if sign-in expires. Never put a token in a remote URL or commit it to this repository.
