# 1.8 — Proportional verification gate (post-merge follow-up)

**Branch:** `naser/proportional-verification-gate` · **Owner:** auditor (Claude Code) · **Requested by:** Naser, 2026-09-26

## Why

The verification gate in AGENTS.md ran all eight steps — full test suite, build,
backend pytest, and a browser check at DPR 1/2 — for every change, including
docs-only edits where none of that can meaningfully fail. That made small process
or doc changes disproportionately slow to prepare locally, even though CI runs the
full gate regardless.

Separately, two smaller frictions had built up:

- The auditor's post-merge `docs/STATUS.md` update went through its own follow-up
  PR (see PR #9, `naser/audit-pr3-and-status`) even when the auditor was merging
  their own branch and could have included the update in that same PR.
- `docs/handoffs/` only ever grows; nothing trims it, so session start's handoff
  read grows indefinitely.

## What was done

- **AGENTS.md, verification gate:** added a scope rule before the numbered steps —
  docs-only changes (only `.md` files or files under `docs/`) run `format:check`
  locally and rely on CI for the rest; code changes without UI impact run the full
  local gate minus the browser check (step 8); UI/rendering changes keep the full
  gate. CI itself is unchanged — it always runs the full gate on every PR
  regardless of local scope, so this only changes what's run locally before
  opening a PR.
- **AGENTS.md, merge rules:** the "after every merge" line now distinguishes
  merging your own work (fold the `docs/STATUS.md` update into that same PR
  before merging) from merging the other role's PR (STATUS.md still needs its own
  follow-up PR, since builder PRs don't touch it).
- **AGENTS.md, session end protocol + documentation rules:** handoff notes are
  capped to a week; anything older gets rolled into
  `docs/handoffs/older-summary.md` as one paragraph per note (oldest first) and
  the individual files are deleted.

## What was skipped and why

- No rollup performed on this PR — all five existing handoff notes are dated
  2026-09-26 (today), so nothing is yet older than a week.
- No change to CI (`.github/workflows/ci.yml`): CI already runs the full gate on
  every PR; the proportionality is a local-workflow saving only.

## Verification

Docs-only change under the new rule it introduces: ran `npm run format:check`
locally (clean for `AGENTS.md`; four pre-existing unrelated warnings on main are
untouched by this diff) and rely on CI for the rest. No UI change, so no browser
check.
