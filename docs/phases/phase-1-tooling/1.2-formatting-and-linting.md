# 1.2 — Formatting and linting

**What was done**

- **Prettier** (exact-pinned) with `printWidth 100`, `singleQuote`, `arrowParens: avoid`, `endOfLine: lf` (rationale in ADR 001). Ignores build output, generated files, and binary asset folders.
- **Repo-wide reformat** in its own commit (`206297e`), recorded in `.git-blame-ignore-revs`: 151 files, +44,012/−8,196 lines. No behavior change — verified by an unchanged test suite and clean typecheck immediately after.
- **ESLint 9** flat config: `eslint-config-next/core-web-vitals` + `/typescript` + `eslint-config-prettier` (Next 16 removed `next lint`; the ESLint CLI is the supported path per the bundled Next 16 docs). `npm run lint` enforces `--max-warnings 0`.
- **Line endings**: `.gitattributes` with `* text=auto eol=lf` + binary rules (`*.glb`, `*.stl`, `*.blend`, `*.png`, …). The index was already LF throughout, so renormalization rewrote zero files — the commit only adds the attributes, and `.git-blame-ignore-revs` didn't need it.
- **File limits**: `scripts/check-file-limits.mjs` (`npm run check:limits`) fails CI for non-test code files over 300 lines or any 500+-character line, with an explicit allowlist of 30 pre-existing oversized files (each annotated with its Phase 2 fate) and 3 long-line files. The allowlist must shrink, never grow.

**Lint resolution breakdown**

- Config, not suppression: the repo's `_`-prefix / rest-siblings unused-value convention encoded in `@typescript-eslint/no-unused-vars` options (~25 findings).
- Mechanical fixes: two `prefer-const` (split a shared `let` list), one ternary-as-statement → `if/else` in `push-to-talk.ts`.
- 32 disable comments with TODOs for findings that need real design work, deliberately not "fixed" mechanically because each fix risks behavior: `react-hooks/set-state-in-effect` (12), `react-hooks/exhaustive-deps` (14), `react-hooks/refs` (5 sites), `react-hooks/globals` (2, test harnesses), `@next/next/no-html-link-for-pages` (1, intentional full reload). Each carries `TODO(phase-2)` (or phase-3 for the reload link) and they're expected to be resolved by the Phase 2 splits.

**Skipped / notes**

- No auto-fix was applied for the react-hooks errors on purpose — moving setState out of effects or ref writes out of render changes rendering behavior, which belongs in Phase 2 slices with per-slice gates, not in a tooling PR.
