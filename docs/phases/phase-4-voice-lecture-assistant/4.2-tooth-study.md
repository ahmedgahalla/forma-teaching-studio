## Delivered scope and decisions

- **A — Authored anatomy:** `tooth-anatomy/` covers all 28 FDI IDs through 14 arch/class entries, mirrored by patient side. Names, roots, cusps/incisal features, morphology, orthodontic relevance and spoken explanations are data. Upper root counts are 1/1/1/2/1/3/3, lower 1/1/1/1/1/2/2; tests compare every ID directly with GLB metadata. Formal/maxillary and classroom/upper wording, canine/cuspid/eye tooth, premolar/bicuspid and six-year molar aliases are supported. Omitted side means patient's right. All content surfaces display “Teaching draft — pending educator review · synthetic model”. General morphology remains pending educator review; model root counts are not claims about all real teeth.
- **B — Action and restoration:** local-only open/view/explain/close actions pass strict field validation, case preflight and dispatch. Open selects and isolates the tooth, shows roots and removes obstructing anatomy. The first study captures its return camera, selection, isolation, roots/gums/labels, arch/view and supporting anatomy. Reopening another tooth keeps that return state. Classroom snapshots include study state, so whole-request Undo/Redo restores both the study and its return path. Loads clear study; case reset/variant/return closes it even when model identity stays the same. Case action routing also works from workflows. Explanation state is applied before adapter narration reaches the 4.1 speaker, HUD and interruption path.
- **C — Surface labels:** six projected DOM directions use tooth-relative axes and correct labial/buccal, palatal/lingual and incisal/occlusal wording. Both directly camera-facing and directly rearward labels are hidden to avoid projecting them onto the tooth. Vectors, output points and DOM nodes are reused; descriptors/bounds are recalculated only when study/pose changes. Cleanup removes the overlay; no new GPU resources were introduced. Existing canvas CSS dimensions are retained.
- **D — Card and entry point:** a 28 px heading, 18 px body/buttons and theme tokens support projection. The card sits beside the model, stacks below at narrow widths and scrolls its details while keeping controls visible. It replaces the lecture explanation console while study is active. Its six sides, Explain aloud and Back buttons all use `teaching.execute`. View exposes Study this tooth for exactly one selected tooth. Unrelated ghosts, appliances, grid, traces and editing overlays are temporarily suppressed without changing their saved settings.
- **E — Grammar:** requested tooth names/numbers, spoken FDI pairs, side aliases, turn/next-side, explanation questions and close phrases parse locally. Existing focus/select/zoom/roots grammar stays covered. “Show all teeth” closes an active study and retains the existing full-arch action outside one. An omitted arch uses the selected arch or asks for clarification. Closing must finish a compound request: subsequent commands are requested separately so they resolve against the restored selection. This matches the existing return-to-workspace boundary.
- **F — Navigation:** active case tooth study takes next/back through buccal → mesial → lingual → distal → occlusal → apical, including wraparound. Prepared cases use stages despite their existing `lessonActive` flag; real short lessons use lesson steps and workflows keep their authored steps. The case adapter distinguishes an actual timeline from an empty workspace. Empty free exploration clarifies locally without applying actions or calling the interpreter, including with the AI preference enabled.

Camera framing is pure, tested math: transformed anatomical axes determine the direction, side views use world +Y up, occlusal/apical views use buccal up. Crown-plus-root bounds target 62% viewport height; narrow screens may constrain size by width. The render loop applies automatic framing before pending snapshot restoration, so exact saved camera state wins on close/undo/redo. DOM card/labels/HUD remain outside the WebGL image export.

The duplicate unused context functions were removed from `parse-clauses.ts`. A single local-only kind list now serves validation and interpreter context filtering. Both new context fields (`toothStudy`, `canStepStages`) and local-action history are stripped before optional backend requests. No backend schema or endpoint changed.

- Host reruns for exact format/lint/format-check/build commands are still required. The repository's tool configuration and inaccessible caches were not changed to hide environmental failures.
- Real browser/device, projected readability, narrow scrolling and DPR checks were prohibited for this task. See the [auditor acceptance request](../../reviews/from-builder/2026-09-27-phase-4-2-tooth-study-review.md).
- Educator approval is still outstanding. No clinical validation is claimed. The [guide](../../TOOTH_STUDY.md) documents anatomy sources, model limitations and patient-side defaults.
