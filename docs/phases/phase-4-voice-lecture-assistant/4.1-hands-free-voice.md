# 4.1 — Hands-free voice-led lecture control

**Branch:** `ahmed/phase-4-voice-lecture-assistant` · **Status:** implemented; full automated gate passed on the host; audit and real microphone/projector checks pending

## Scope and behavior

1. Optional hands-free recognition starts only through an explicit session gesture. Hold-to-talk remains the default and retains release-to-submit semantics. Continuous recognition restarts with bounded backoff and turns off on permission/service/microphone failures or three network failures. Forma/hey Forma/okay Forma/ok Forma and data-listed recognizer aliases gate final utterances. A bare wake phrase arms one six-second follow-up. Non-wake finals never reach command processing or storage. Blur cancels hold capture but leaves hands-free active. Settings persist mode preference, en-US/en-GB and spoken replies defensively under `forma-voice-settings`.
2. A DOM voice HUD sits at the bottom of both model viewports in normal and lecture modes. It shows the persistent red Listening indicator, transient interim speech, Heard/result/error feedback and narration captions. Desktop main text is 32 px at 1600 px width, high-contrast in both themes; narrow layouts scale down. Completed feedback fades after four seconds with reduced-motion support. It does not take focus or pointer events.
3. One presenter hook in the shared provider replaces the workflow-only arrow handler. PageDown/Right advances and PageUp/Left goes back; M/B/period toggles listening. Plain focused buttons permit navigation; editable targets, dialogs, actual open menus and modified/repeated keys do not. Workflow mode maps to `workflow next/previous`; case with an active short lesson maps to `lesson-step`; other case contexts map to `stage next/previous`. These use `runControl` and existing actions.
4. Local grammar accepts next/next step/go on/continue/go to the next step and back/previous/go back/previous step in all contexts. FDI digit-pair normalization preserves quantity values and is mirrored by the frontend, backend and shared fixtures. Stop listening is controller-level and works even when Analyze is enabled.
5. Optional voice-originated confirmations use the shared interruptible speech path, with at most twelve words for successful summaries and full clarifications. Typed requests do not acquire automatic speech. Authored narration is not repeated as a confirmation. Recognition pauses before speech output and resumes after completion, error or interruption. Stop/Escape and new hold speech interrupt output; stale requests cannot announce a later confirmation.

## Files and design

- `src/lib/voice/`: wake gate, hands-free lifecycle, validated settings and shared speaker with co-located tests. Long narration is spoken and captioned in short word-bounded chunks, with recognition paused across the entire sequence, to keep prose below the model centre. `push-to-talk.ts` adds only an optional language argument, retaining existing behavior and tests.
- `TeachingController.tsx`: integrates services through `submitText` and the existing runtime; context/type definitions move to `teaching-context.ts` with stable re-exports. `useTeachingVoice.ts` and `useHoldToTalkKeys.ts` own browser lifecycle and capture controls. No extra execution path.
- `VoiceHud`, `HandsFreeToggle`, `VoiceSettingsFields` and their own CSS; placements in `CaseViewport`, `OpeningCommandDock`, `WorkflowStudio`, `DialogsSetup`; `DialogsInfo` shortcut guidance.
- `usePresenterKeys`, `classroom/parse-navigation`, `classroom/parse-arrangement`, `plan-build`, classroom-language modules and fixtures. Arrangement parsing is extracted unchanged to leave the near-limit plan builder below 300 lines.
- `teaching-runtime.ts`: Stop updates the heard transcript; file length remains unchanged. No new actions, allowlist entries, packages, endpoints or viewer render-loop work.
- Guides, phase index and [ADR 004](../../decisions/004-hands-free-voice.md) updated together. Auditor-owned STATUS and AGENTS are untouched. No git mutations or dependency installation.
- Tool configuration is unchanged. The builder temporarily excluded the orchestrator's nested worktree and Python cache in `package.json`, `eslint.config.mjs`, `tsconfig.json` and `vitest.config.mts`; the orchestrator removed that worktree and reverted all four edits before committing (lesson 13). No dependency or lockfile changes.
- Orchestrator review change: in hands-free mode the HUD shows interim text only when it is addressed to Forma (starts with the wake phrase, or follows a bare wake word). Other classroom speech is never displayed (`hands-free.ts`, `wake-phrase.ts` `armed()`, new test).
