# 4.4 — Explain by voice: glossary and tooth anatomy tour

**Branch:** `ahmed/phase-4-voice-lecture-assistant` · **Base:** `24231c7` · **Date:** 2026-09-27 · **Status:** implemented for orchestrator review; verification recorded below.

No git state changes, installs, new dependencies, asset changes, STATUS/AGENTS edits or allowlist additions. The orchestrator reviews and commits. This branch retains its existing PR #13 dependency.

## Delivered

- **A — Authored glossary:** 40 terms in `src/lib/glossary/`, separated into anatomy, occlusion and movement data. Every entry has aliases, a one- or two-sentence definition, related IDs and “Teaching draft — pending educator review”. Thirty-seven entries have existing visual action sequences. Carabelli opens tooth 16 palatally; movement terms select an authored case variant, paused at progress zero. Angle classes describe the dental classification without claiming the model depicts skeletal relationships. PDL/bone explanations load the reference mouth before showing schematic supporting anatomy. See [Glossary](../../GLOSSARY.md) for sources and review limits.
- **B — Deterministic explanation:** what is/what's/what are, define, explain, tell me about, and show me with known glossary terms resolve locally. Existing display/tooth/narration commands retain precedence. Unknown explanation terms clarify locally with examples, including when the AI interpretation preference is enabled. Unrecognized “show me” wording retains the existing interpreter behavior because this form is glossary grammar only for known terms. Explicit Analyze stays separate. Strict local-only glossary actions, AI context stripping, routing, preflight, dispatch, narration and snapshots all participate in the shared runtime. Only exact authored visual sequences cross the existing single prepared-case command boundary.
- **Definition card:** a separate right-hand grid region (below the viewport on narrow screens) contains the term, complete definition, related-term buttons and review notice. It replaces the tooth explanation card while open and never overlays the model centre or HUD. Voice “close the definition”/“hide that” and Close definition use the runtime. Closing the definition preserves the visual so discussion can continue. A complete visual-plus-definition request undoes/redoes as one scene snapshot.
- **C — Tooth anatomy tour:** ten authored steps: 11 labial and palatal; 13 labial; 14 mesial; 16 occlusal, palatal and buccal; 46 occlusal and buccal; full mouth. “Start the tooth anatomy tour”/“start the tooth tour” starts at step zero from the synthetic free workspace. Next/clicker advances the lesson before considering tooth sides. Explain this step narrates its caption. Previous/restart preserve study, camera, anatomy and isolation. The last step restores the full mouth but retains its ribbon for final-caption narration; Close/end/back to full mouth ends the lesson. Lesson start/close are strict local-only runtime actions; Library lesson selection now uses that same route.
- **D2 — Speech fallback:** missing APIs, thrown failures, speech error events and silent start/stall failures show ordinary chunked narration with “Speech unavailable — showing text”. Text timing estimates a 150-word/minute voice at the existing 0.95 rate, with a two-second minimum per chunk. Stop/Escape/new capture interrupt it. Hands-free resumes during text-only fallback because there is no output audio to feed back. Other runtime failures still use the existing error presentation.
- **D — Discovery:** shared Ask Forma examples appear in Guide and Library. The opening screen gains no controls.

## Decisions and deliberate test changes

- `lecture.test.ts` now expects five lessons instead of four and checks the first tour action explicitly. The four existing geometric lessons still begin with reset. No clinical or educator validation is implied.
- Five obsolete speaker tests that expected speech failures to reject were replaced by fallback regressions; the new behavior intentionally succeeds through captions. The BVH oracle and its timeout are unchanged.
- All local-only action kinds use the existing shared `LOCAL_ONLY_KINDS` list for both strict validation and interpreter history filtering. Glossary presentation state is also stripped from AI context.
- Small helper modules contain lesson controls, authored glossary-plan recognition, workspace preflight and interaction hit-testing. Allowlisted files do not grow; no file-limit exemption was added.
